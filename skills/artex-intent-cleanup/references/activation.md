# 接入 ARTEX worker

这份技能用于 ARTEX 的原生技能目录，目录由 `ARTEX_SKILL_DIR` / `config.json` 的 `skill_dir` / 程序旁的 `skills/` 决定，不是 Codex 的全局技能目录。

## 预览模式

1. 将整个 `artex-intent-cleanup/` 放入实际技能目录，保留 `policy.json` 的 `preview`。
2. 在 ARTEX 智能体管理中给 `worker` 授予该技能的可见权限，保留其原有全部技能选择。
3. 备份当前 worker 提示词并追加下面的片段，不覆盖原提示词。若安装版本有独立的 worker 提示词变体，对实际使用的变体做同样追加。

```text
【意图文件收尾】
每条意图开始时加载 artex-intent-cleanup 技能，遵循其中的文件分类和输出限制。在正常完成意图、成功写回结果后、最终回答前，按技能执行本意图临时文件预览；policy.json 为 preview 时只汇报、不删除。只有维护者已经启用 delete-disposable 且确认所有业务保护条件成立，才按技能生成并执行确切文件计划。暂停、异常、取消、待审批、预算耗尽和仍有写入时保留文件。不清理其他意图，不修改清理策略，不绕过脚本。无法调用技能或清理失败时简要报告，不阻塞已完成业务结果的交付。
```

4. 用一个新的正常意图检查：技能确实被加载、目录正确、最终回复给出预览、原有证据可读。已在运行的会话可能沿用旧提示词和工具装配，不承诺即时覆盖。

仅绑定技能不会强制调用。上述提示词要求在模型正常完成时执行；强制退出、超时收尾（可能没有 Bash）、服务崩溃时仍可能跳过。要保证引擎层面的每次终态执行，需要单独实现并验证终态钩子、并发/续跑保护和引用保留策略。

## 启用实际删除

在用户已经看过清理范围并明确授权自动删除后，由维护者将 `policy.json` 的 `mode` 改为 `delete-disposable`，不扩大目录范围。技能执行者不能自行切换。开启后的损失是被清理临时文件无法再按原路径读取；业务判断错误仍可能影响复现，因此无法确认用途的文件必须保留。

脚本要求 macOS/Linux、Python 3、支持目录文件描述符的系统调用，以及 `lsof`。缺少 `lsof`、文件仍被打开或检查报错时拒绝删除。占用检查是瞬时检查，不能代替结束全部写入者；不能在其他进程仍可能打开这些文件时使用。

## 停用

先把策略改回 `preview`，再按需移除追加的提示词段和 worker 的这一项技能绑定，保留原有配置。应用操作启动时读取策略，已经开始的删除不因后来切换而撤销。停用不会恢复已删除文件。
