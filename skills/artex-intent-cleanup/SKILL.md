# 意图文件收尾

只处理系统提示给出的本意图工作目录 `data/tasks/任务ID/i意图ID`。读取本技能的 [policy.json](policy.json)：`preview` 只预览；只有用户已授权、且维护者已将模式改为 `delete-disposable` 时才执行删除。不要自行修改策略、清理脚本或用其他命令绕过限制。

这是 ARTEX 内部 worker 技能。技能放入目录不会自动触发；部署者须按 [接入说明](references/activation.md) 绑定 worker 并追加收尾提示词。技能不是引擎退出钩子，异常退出、取消、超时或工具被禁用时可能无法执行，不声称覆盖每次退出。

## 开始意图时

1. 从系统提示读取实际工作目录；不要仅靠当前 shell 目录推断任务归属。命令中的 `RUN_DIR` 是该绝对路径，`SKILL_DIR` 是本技能实际安装目录。
2. 需要生成可丢弃文件时，使用脚本 `--init` 新建带归属标记的 `.artex-disposable/`。脚本拒绝接管已有但无标记的目录。该目录仅放本轮创建、用完即弃且可重算的普通临时文件；不放子目录，不把历史文件搬进去以取得删除资格。

```bash
python3 "$SKILL_DIR/scripts/cleanup_scratch.py" "$RUN_DIR" --init
```

3. 复现脚本、原始证据、请求/响应、报告、截图、下载原件、仓库、凭据、会话、需要交给后续意图的结果，保存在本意图目录内的持久位置。重算需要重新探测目标、重复付费、重新登录或可能得到不同结果的文件，不属于可丢弃临时文件。

## 每次正常收尾

在正常工具阶段、最终回答前执行，给收尾保留工具调用机会：

1. 先确认本意图结果已通过正常业务工具成功写回。仅写一句总结或保存文件路径，不能代替实际保存证据；保留完整复现所需的请求、响应、参数、脚本和引用文件。
2. 确认本意图创建的写文件进程已经结束或已正常关闭；只关闭自己创建且确认归属的资源，不使用全局杀进程命令。其他 worker、浏览器或共享工具还在使用的文件保留。
3. 运行预览。预览只读目录元数据，不读取文件正文，也不会遍历其他意图：

```bash
python3 "$SKILL_DIR/scripts/cleanup_scratch.py" "$RUN_DIR"
```

4. 逐项判断临时文件是否仍被代码、报告、事实、会话、后续意图或人工交付引用。无法证明可丢弃的文件保留；不要把“大、旧、叫 log/tmp、已写总结”当作删除依据。脚本只能检查文件边界，不能判断业务依赖。
5. 对确认可丢弃的文件，用重复的 `--file` 参数列出确切文件名并生成计划；不使用通配符、不列整个目录。下例仅演示参数，实际文件名必须来自本次预览：

```bash
python3 "$SKILL_DIR/scripts/cleanup_scratch.py" "$RUN_DIR" --plan --file scratch-search.txt --file scratch-sort.txt
```

6. `preview` 模式到此结束，汇报预计大小；即使用户在任务里泛称“清理”，也不能自行切换策略。已启用 `delete-disposable` 且前述业务条件全部满足时，使用刚返回的 `plan_path`：

```bash
python3 "$SKILL_DIR/scripts/cleanup_scratch.py" "$RUN_DIR" --apply-plan "$PLAN_PATH" --work-complete --writers-stopped
```

脚本逐项检查归属、符号链接、硬链接、文件占用和计划后的变化，仅删除计划中指定的普通文件，保留目录及审计记录。两个确认参数是执行者对业务条件的声明，不是数据库状态校验。失败时保留剩余文件并报告原因，不改用 `rm -rf` 或绕过检查。

7. 最终回复简要注明清理状态：预览/实际删除/跳过、文件数和字节数、保留原因。脚本报告的大小是文件计量，不保证等于 APFS、快照或磁盘界面的即时可用空间变化。不为清理本身新增探索事实。

## 必须保留的范围

- 本意图 `.artex-disposable/` 以外的全部文件，包括 `cmd-output/`：大工具输出在这里保存全文，执行记录可能只保存预览和路径。
- `data/transcripts/`、`data/worker-outcomes/`、`data/evidence/`、流量库及其 blobs、任务归档、工具与依赖、配置和密钥、PostgreSQL/SQLite 文件及 WAL。
- 暂停、待审批、网络或模型错误、步数/时间耗尽、正在重试、等待人工补充的意图数据。异常结束不等于业务完成；不为清理而恢复或另派意图。
- 已结束意图也可能被后续 worker 读取或重新打开。自动清理仅适用于本来就允许丢弃的临时文件；已写入事实或经验库不等于保存了完整原始文件。

历史任务的大文件只列出大小、用途和归档建议。压缩替换也会改变原路径的读取方式，属于另一次明确限定范围的维护操作。

## 防止再次膨胀

- 搜索限定输入目录、扩展名或文件清单，限制结果量；输出文件必须在搜索输入之外，并显式排除 `.artex-disposable/`、`cmd-output/`、日志输出和无需搜索的依赖/`.git/`。不要执行把结果写回搜索范围的递归 `grep ... . > hits.txt`。
- 对长时间命令设置合理时限和输出上限；记录复现证据及必要上下文，避免无限追加重复调试输出。诊断大文件先查看大小和有限片段，不把全文打印到工具输出中再复制一份。
- 不重复下载已有可复用的大文件；复用前确认来源、版本及引用路径。不要为了清理而重新进行网络探测。
