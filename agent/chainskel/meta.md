# chains-meta L3 决策骨架（以真实执行与证据判断为准）
- 场景:多轮没有新信息|判据:先分清工具是否真正执行、前置是否具备、响应是否可重复；相似输出不能证明整条路线已穷尽|转向:暂停重复动作，记录已测条件、卡点和恢复触发条件
- 场景:细微响应差异|判据:差异可能来自随机噪声、缓存、服务不稳定；只有可重复并减少未知才是进展|转向:保留必要对照，避免凭一次变化持续投入
- 场景:请求状态码和长度相同|判据:只说明响应相似，可能来自应用通用错误页、权限门、代理或统一拦截；不能单凭此断言没到应用|转向:检查已有请求/响应内容及应用迹象，证据不足标未知
- 场景:固定延迟或请求变慢|判据:网络、排队、限流和服务负载均可能造成相似现象，不能凭时长认定防护或特定执行行为|转向:先排查环境并比较可复现观测，不把超时当阴性
- 场景:工具返回阳性或阴性|判据:均需核对适用前提、真实输出和必要对照；扫描名称与版本匹配不是确认|转向:只记录证据支持的范围，受阻与未测条件保留
- 场景:准备完成却没有核心检查|判据:环境、脚本、会话的就绪不等于验证成立；审批等待不算已执行|转向:交接具体缺口和可复用产物，不重做整套准备或换编号重复派发
- 场景:预算结束|判据:保留已经执行的步骤、证据与未完成条件，预算耗尽不是目标安全|转向:恢复后从已核实进度继续；结果不明的操作先查证
- 场景:一个问题需要多步前置|判据:依赖前一步实际产物的步骤应串行，来源锚点不代表前置成功|转向:仅派当前可执行步骤，不让下游空转
- 场景:队列为空但目标未满足|判据:可能确实缺人工材料、审批或环境，不意味着必须制造可执行工作|转向:存在独立、授权且就绪的问题才派发，否则说明等待与恢复条件
- 场景:评价方向是否走完|判据:结论必须限定实际测试过的前提与条件；新信息可改变旧假设，无新证据不重试|转向:保留未测部分与复查触发条件
- 场景:已有目标相关证据|判据:先核对它是否直接满足验收条件，事实数、请求数和覆盖率不能替代结果|转向:保存可核验来源与理由，不凭风险名称宣布完成
