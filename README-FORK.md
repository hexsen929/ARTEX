# ARTEX-ymh 能力移植说明

本 fork 在 `85cc3d9`（RuoJi6 更新与本地定制、Norma 0.4.3）基础上，移植 `panda0x123/artex-ymh@48adc7f` 的已实现功能。来源项目基于更早的 ARTEX 分支，本次不是降级替换，也不引入其原有发布源或发布密钥。

## 已实现功能范围

| 子系统 | 移植内容 | 部署与验证边界 |
| --- | --- | --- |
| 会话与资源 | 会话台账、探活、工作台、受管文件暂存、反向连接管理 | 需要对应外部运行时与工具；重启后的状态应以探活结果为准，不把台账记录视作仍然在线 |
| 隧道与路由 | 隧道编排、健康检查、任务专属流量代理、上游路由切换 | 宿主侧工具需匹配 OS/CPU；指定任务代理故障应明确报告，不静默改变出口 |
| 内网工作台 | 任务过滤的会话/隧道/凭据台账与主机/网段/链路图 | 拓扑来自已记录信息，不承诺自动发现所有网络 |
| 阶段编排 | 新范围待审批、后续任务移交、内网提示词 | 保留人工审批入口；子任务继承的只读历史与可使用资源须按任务归属处理 |
| 凭据 | 独立结构化、来源、验证记录和加密存储 | 与原任务情报的凭据整理并存；加密数据依赖原 `jwt.key` |
| 规划与复测 | 九类 chains 骨架、停滞转向、分类反证清单、独立复测 | 清单是给模型的检查上下文，不是逐项机械验真；继续保留 confirmed/unverified/blocked/rejected 状态及原始证据 |
| 防护 | 门控、范围审查、出口敏感指纹检查、静态蜜罐签名、临时自动审批 | 自动审批默认关闭且不豁免 deny；L1 蜜罐评分不是准确概率，阴性也不证明不存在蜜罐 |
| 运维 | doctor、工具清单、systemd、Docker 源码构建、调用墙钟与冻结感知 | 工具清单不等于已安装；调用墙钟是单次模型调用预算，不是 Worker 固定收尾时限 |

## 保留的当前版本能力

### 本轮接线与原设计边界

- 任务专属 MITM 只独立监听、CA 和上游路由，录制写入同一个全局索引与证据树；原流量查询、漏洞绑定和归档继续读取完整记录，避免任务录制成为孤岛。
- 默认 Playwright `browser` MCP 在真正调用时接入任务代理，并为每轮创建隔离配置；不改全局 MCP 记录，不把代理口令写进公共日志。浏览器 HTTPS 的证书信任仍需按所选浏览器明确配置；`NODE_EXTRA_CA_CERTS` 仅覆盖 Node 运行时，不能等同于已安装浏览器系统信任。远程 CDP、扩展/持久共享上下文等不适用自动隔离的配置会明确报错，第三方 MCP 仍需按其协议配置。
- HTTP 会话驱动目前使用显式直连传输；`session_exec/read/write` 有工具活动记录，但不能据此声称所有会话 HTTP 请求均经 MITM，也不包含任意层级 HTTP 会话的自动路由。隧道计划当前主要是单段；完整任意多跳、SSH 驱动等设计目标仍需单独实现和验证。
- 归档和删除前检查存活会话、隧道、监听及暂存等受管资源；有活资源时先明确要求回收，不自动终止其他任务共享的会话。恢复加密记录要求原实例密钥，归档包不包含密钥本身；恢复不会自动重连会话或隧道。
- 子任务可单独解除显式共享会话绑定，再归档自身；该操作不停止父会话，也不影响其他任务。全局删除会话与解除本任务关联是两个不同操作。
- 保留用户已经自定义的审批工具列表；升级后请核对新会话、文件写入、隧道等工具的审批覆盖，原有自定义设置不会被静默重置。

### 既有功能

- RuoJi6 的日历计划、漏洞归并/统一报告、通知推送、任务情报和审批增强。
- 独立漏洞验证状态、人工结论与证据版本；未确定结论不被强制转成确认或丢弃。
- Codex Responses/指令文件/上下文配置、LLM 配置链搜索与刷新、共享实际请求重试预算和可解释 Worker 终态。
- MCP 缓存 schema、按需私有连接、满额排队、取消清理、状态保留与不重放已发出的操作。
